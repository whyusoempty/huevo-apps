# Приложение «Тесты» для huEVO

Игра для huEVO: каталог тестов («кто ты из…» и викторины) в духе миниТестов старого ВК. Игроки проходят тесты, получают картинку-коллаж с результатом и сами создают тесты в конструкторе. Автору можно отправить монетки.

Стек: Cloudflare Workers + D1, Hono, Preact + Vite + TypeScript. Планирование и решения — [PLAN.md](PLAN.md).

## Запуск у себя на Cloudflare

Нужен аккаунт Cloudflare, Node 20+ и `npx wrangler login`. Реальные значения (id базы, домен, `HUEVO_CLIENT_ID`) удобно держать в локальном `wrangler.<имя>.jsonc`: такие файлы в `.gitignore`, деплой через `npx wrangler deploy -c wrangler.<имя>.jsonc`.

```bash
npm install
npx wrangler d1 create huevo-tests            # вписать database_id в wrangler.jsonc
npm run db:remote                             # миграции
npx wrangler secret put HUEVO_CLIENT_SECRET   # client_secret приложения из huEVO
npx wrangler secret put JWT_SECRET            # любая длинная случайная строка
```

В `wrangler.jsonc` → `vars`:

- `HUEVO_CLIENT_ID` — client_id приложения;
- `ADMIN_IDS` — `hu_user_id` админов через запятую (раздел «Жалобы» для модерации);
- `COMMISSION_PCT` — комиссия с донатов автору, % (по умолчанию 10);
- `DEV_LOGIN` оставить `0` (при `1` можно войти без подписи — только для локальной разработки).

Темы оформления («Классика ВК», «Мягкая», «Тёмная») переключаются ссылками внизу страницы, выбор хранится в браузере игрока.

Свой домен: раскомментировать `routes` и указать поддомен зоны, которая есть в аккаунте. Затем:

```bash
npm run deploy
```

Что указать в настройках приложения huEVO:

- **Адрес игры** — ровно origin воркера (`https://…`), без редиректов: при редиректе SDK перестаёт отвечать;
- **Вкладка «API» → «Коллбек оплат»** — `https://<домен>/api/callback/payment`.

Пока приложение в черновике, huEVO запускает его в тестовом режиме: монетки не списываются и не начисляются — удобно проверить вход, оплату и выплату.

Стартовые тесты (Наруто, животное, викторина) создаются сами при первом запросе, если база пустая.

## Локальная разработка

```bash
cp .dev.vars.example .dev.vars    # DEV_LOGIN=1 — вход без huEVO (?dev=2 — другой пользователь)
npm run db:local
npm run dev                       # vite build + wrangler dev → http://localhost:8787
node scripts/smoke.mjs            # смоук-тест API (HUEVO_CLIENT_SECRET=dev-secret)
```

## Устройство

- `src/worker` — API: вход по `hu_hash`, каталог, прохождение (результат считает сервер), конструктор, картинки (хранятся в D1), жалобы и автоскрытие, донаты (`/api/donate` → payments → коллбек → credits), cron для дожима платежей и выплат.
- `src/web` — интерфейс в стиле ВК 2012. Результат — картинка-коллаж, которую рисует canvas (`collage.ts`); аватар игрока берётся через `/api/avatar`, чтобы canvas можно было выгрузить в JPEG.
- `src/shared/const.ts` — лимиты и категории для обеих частей.
- `migrations` — схема D1.
- `public/seed` — картинки стартовых тестов (Wikimedia Commons, только Public domain / CC0, см. `CREDITS.md`; скрипт `scripts/fetch_seed_images.py`).

## Важно знать

- Постить на стену игрока из игры нельзя (в SDK нет такого метода), поэтому игрок сохраняет картинку результата и выкладывает сам. `huevo.share()` делится ссылкой на игру, не на конкретный тест; для этого у теста есть короткий код.
- Модерация контента ложится на нас: жалобы (5 штук скрывают тест автоматически), бан автора, запрет ссылок в текстах, лимиты на создание и загрузку.
- Донат: платёж от игрока → кошелёк игры → `POST /credits` автору (минус комиссия). Если выплата не прошла (например, автор ни разу не открывал опубликованную игру), она остаётся в очереди и повторяется по cron.
- Платежи и выплаты проверены только по документации; на реальном huEVO их надо прогнать в тестовом режиме.
