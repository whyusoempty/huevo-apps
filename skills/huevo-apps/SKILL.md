# Приложения для huEVO

huEVO показывает приложение **во фрейме** (`iframe`) со своей страницы. Приложение это обычный сайт на домене разработчика плюс его собственный backend. Платформа даёт: подписанные параметры запуска (кто игрок), JS SDK для диалогов (оплата, «поделиться», профиль, ссылки) и серверный Apps API (профили, кошелёк игры, оплаты, выплаты).

Доки (источник правды, они меняются, перечитывай перед работой): https://huevo-docs.lunnaholy.workers.dev/apps/

## Порядок работы

1. **Прочитай доки** (ссылка выше) и `references/platform.md`. Не выдумывай факты о платформе: нет в доках, значит скажи, что не знаешь.
2. **Спланируй**: экраны, таблицы, какие API/SDK-функции нужны, что монетизируется. Коротко согласуй с владельцем только то, что нельзя выбрать по умолчанию.
3. **Каркас**: Workers + D1 + Hono + Preact (см. `cloudflare.md`). Хэш-роутинг (`#/страница`), mobile-first (на экранах уже 700px фрейм вертикальный 9:16).
4. **Вход**: `/api/login` проверяет `hu_*` и выдаёт свой JWT; токен в `localStorage`, заголовок `Authorization`. Добавь `DEV_LOGIN` для локальной разработки (на проде выключен).
5. **Функции**: сервер считает всё сам (результаты, награды, цены), клиент только присылает действия.
6. **Платежи/выплаты**, если нужны: цепочка из `patterns.md`, идемпотентность, одна выдача на `intent_id`, `test` из проверенного `hu_mode`.
7. **Проверка**: типы, сборка, смоук-тест API скриптом, скриншоты в мобильной и ~700px ширине. Что проверить можно только внутри huEVO (вход, оплата, `shareContent`, `hu_start`), прямо пометь как непроверенное.
8. **Деплой** и карточка приложения: логотип 1:1 ≥200px (обязателен для модерации), баннеры 4:3 и 16:9, описание ≤1000, до 5 тегов, адрес игры и коллбек оплат.
9. **Передача**: репозиторий без секретов, README с шагами запуска, архив `git archive`.

## Жёсткие правила

- **Личность игрока доказывает только подпись `hu_hash`, проверенная на сервере.** Данные из `huevo.init()` и `launchParams()` на клиенте ничего не доказывают. В подпись входят **все** `hu_*` кроме `hu_hash` (набор растёт, `hu_start` тоже), никакого фиксированного списка.
- Секрет `client_secret` только на сервере (`wrangler secret put`), никогда в репозитории, логах, чате и фронтенде. Если секрет показали в чате, предложи перевыпустить.
- Итог платежа берётся **только** из `GET /payments/{intent_id}` или подписанного коллбека, не из результата `confirmPayment` и не из события `payment` (их можно подделать). Выдавай покупку один раз на `intent_id`.
- В `POST /payments` и `POST /credits` поле **`test` обязательно**, его значение = `hu_mode === 'test'` из **проверенных** параметров запуска текущей сессии.
- `idempotency_key` (1–64 символа) строй от события в твоей БД (`don-<id>`), при ретрае используй тот же ключ.
- SDK подключай **только** со `https://huevo.su/static/js/huevo-apps-v1.js`.
- Во фрейме нельзя `alert/confirm/prompt`, `window.open`, `target=_blank`, буфер обмена, `requestFullscreen`, камеру/микрофон. Делай свои модалки, внешние ссылки через `huevo.openLink`, полноэкран через `huevo.fullscreen`.
- Сессия через токен в `localStorage`, а не cookie (сторонние cookie во фрейме блокируются).
- Адрес игры = конечный origin без редиректов, иначе SDK отвечает `timeout`.
- Весь пользовательский текст рендерить как текст (никакого `innerHTML`), на сервере фильтровать ссылки, ставить лимиты частоты, давать жалобы и бан.
- Монэтки из кошелька игры владельцу **не выводятся**, они уходят только игрокам через `credits`. Прямого перевода игрок→игрок нет: донат = платёж в кошелёк игры + выплата получателю.
- Реальные ключи и секреты в общий конфиг не клади: общий `wrangler.jsonc` с заглушками, реальный в отдельном локальном файле вне git.
