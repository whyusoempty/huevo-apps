# Платформа huEVO: что нужно знать

Источник: https://huevo-docs.lunnaholy.workers.dev/apps/ (проверено 2026-10; перечитывай, доки обновляются).

## Что такое приложение

- Сейчас единственный тип: **Игра** («Бот» помечен «скоро»).
- Страница приложения `https://huevo.su/apps/launch/{app_id}` (название, лого, баннер, описание, автор, «Играть»). Страница игры `https://huevo.su/apps/{app_id}` держит фрейм.
- Фрейм грузит адрес игры из настроек, добавляя подписанные `hu_*`.
- `app_id` числовой, приходит во фрейм как `hu_app_id`. `client_id` это отдельный идентификатор для Apps API (строка, видна во вкладке «Ключи доступа»), не путай их: ссылки `huevo.su/apps/launch/{id}` строятся из числового `app_id`.

## Статусы

Черновик → На проверке → Опубликовано / Отклонено; Отозвано (владелец скрыл). Черновик, проверка, отклонено, отозвано видят только владелец и тестировщики. Если владелец заблокирован/удалён, API отвечает `app_blocked` (403).

## Режимы запуска (`hu_mode`)

| Условие | `hu_mode` | Операции |
|---|---|---|
| Не опубликовано / отозвано | `test` | всегда тестовые |
| Опубликовано | `live` | реальные (если `test:false`) |
| Новая версия до одобрения (`https://huevo.su/apps/{id}?v=new`) | `test` | режим операции задаёт поле `test`; шли `test: true` для всей сессии с `hu_mode=test` |

В тесте: монэтки не списываются и не начисляются, баланс игрока и лимиты не проверяются, уведомления не шлются, получателем выплаты может быть любой существующий пользователь, коллбек приходит с `test:true`. Заморозка кошелька действует и в тесте.

## Игроки

Пользователь становится **игроком**, когда впервые открыл страницу игры опубликованного приложения. Выплаты в `live` возможны только игрокам (`not_a_player` иначе).

## Фрейм

- Соотношение 16:9, 4:3 или 3:2 (настройка «Фрейм игры»); на экранах уже 700px всегда 9:16, на весь экран. Проектируй mobile-first.
- Sandbox: `allow-scripts allow-same-origin allow-forms allow-pointer-lock`.
  - Можно: скрипты, `localStorage`/cookie своего домена, формы, Pointer Lock, автовоспроизведение, геймпад.
  - Нельзя: новые окна/вкладки (`window.open`, `target=_blank`), навигация верхнего окна, `alert/confirm/prompt`, `requestFullscreen`, камера, микрофон, геолокация, Payment Request API, буфер обмена.
- `Referer` во фрейм не передаётся. Сторонние cookie могут блокироваться, поэтому сессия на токене.
- Origin фрейма (схема, домен, порт) должен точно совпадать с адресом в настройках. Редирект на другой origin ломает SDK (`timeout`). Свои query и фрагмент в адресе сохраняются, любые `hu_*` из настроек удаляются и заменяются платформенными.

## Лимиты приложения

10 приложений на аккаунт, 50 тестировщиков, 5 тегов, название 2–64, описание ≤1000, адрес игры ≤300 (`https://`; `http://` только localhost/127.0.0.1; домен huEVO нельзя).

## Создание

Раздел «Приложения» (`https://huevo.su/apps`) → «Создать»: тип Игра, название, адрес игры. После «Создать» открывается вкладка «Ключи доступа» с `client_secret` (**показывается один раз**). Дальше `https://huevo.su/apps/{id}/edit`:

- **Основное:** название, описание, адрес, фрейм, **логотип 1:1 ≥200px (обязателен)**, баннер 4:3 (≥400px шир.), баннер 16:9 (≥640px), автор (вы или сообщество), теги (≤5).
- **Ключи доступа:** `client_id`, `client_secret`. Перевыпуск секрета сразу аннулирует старый: API-запросы с ним отклоняются, подписи `hu_hash` открытых приложений недействительны (игрокам перезагрузить).
- **API:** базовый адрес и **адрес коллбека оплат** (`https://`, до 300 символов, публичный, не домен huEVO, только порты 80/443; пусто = выключено).
- **Тестировщики:** по `@имя`/ссылке, до 50. Видят приложение до публикации, запуск в `test`.
- **Кошелёк:** баланс, пополнение (реальное пополнение возможно только у опубликованного приложения).
- **Публикация:** статус, отправка на проверку, отзыв, удаление (нужно ввести название, нельзя пока на кошельке есть монэтки).

## Модерация

1. Загрузить логотип (без него заявку не принимают).
2. «Публикация» → «Отправить на проверку».
3. **Правка настроек во время проверки возвращает приложение в «Черновик»**, заявку подавать заново: сначала всё проверь.
4. Одобрено → «Опубликовано», режим `live`. Отклонено → причина во вкладке «Публикация».
5. Опубликованное: правки названия/описания/адреса/фрейма/картинок уходят в новую версию и снова идут на проверку, игроки видят старую. Автор и теги применяются сразу. Неодобренная версия может быть только одна.
6. Админы могут снять с публикации, поставить галочку «проверено», плашку 18+ (казино и подобное). Пользователи могут жаловаться на приложение.

Критерии отказа в доках не описаны.

## Монетизация (кратко, детали в sdk-api.md)

- У приложения свой **кошелёк**. Платёж игрока (`payments`) пополняет его, выплата (`credits`) списывает на игрока.
- Вывод монэток владельцу невозможен, только выплаты игрокам.
- Лимиты `live` (сутки по Москве): одна операция 1–100 000, оборот приложения 1 000 000, оборот с одним игроком 100 000. Это значения по умолчанию.
