# Грабли (на которые уже наступили)

## Платформа

- `huevo.share()` **не принимает аргументов** и шарит только ссылку на игру. Для картинки и текста есть `shareContent`; для ссылки на конкретное состояние: `?start=` и `hu_start`.
- Пока приложение не опубликовано, оно в `test`: реальные монэтки не двигаются, а «Опубликовано» меняет режим на `live`, и ничего в коде менять не надо, если `test` берётся из проверенного `hu_mode`.
- Поле `test` в `payments/credits` **обязательно**. Не забудь для платежей и выплат.
- Из кошелька игры нельзя вывести монэтки себе. Комиссия с донатов остаётся в кошельке и тратится только на выплаты игрокам. Не обходи это чужими аккаунтами.
- `credits` в live требует, чтобы получатель хоть раз открыл опубликованную игру (`not_a_player`). Не падай: оставь выплату в очереди и повторяй.
- Коллбек: `https`, порт 80/443, публичный адрес, не домен huEVO, без редиректов. Доставка не гарантирована, нужен запасной опрос.
- Правка настроек во время проверки возвращает приложение в «Черновик». Логотип обязателен.
- Перевыпуск `client_secret` ломает все прежние подписи; секрет показывается один раз.
- Конструктор приложения требует `https://` и адрес не на домене huEVO.
- Раньше лимит `share` был 3/мин, сейчас в доках 15/мин: смотри актуальные доки.

## Фрейм

- **У huEVO два домена: `huevo.su` и `huevo.departament.site`.** SDK по умолчанию общается только с origin, откуда загружен скрипт (`huevo.su`), поэтому на втором домене `share`, `shareContent`, `confirmPayment`, `openLink` молча не отвечают, а вход работает (подпись берётся из URL). Лечение: `data-origins="huevo.departament.site"` на теге script и/или `huevo.init({origins:['huevo.su','huevo.departament.site']})` до остальных вызовов. Тестируй приложение на обоих доменах.

- Canvas, куда нарисован чужой cross-origin ресурс, нельзя выгрузить (`toBlob` бросает ошибку). Проксируй аватар через свой origin.
- `<input type="file">` во фрейме работает (sandbox allow-forms), но `download` и буфер обмена нет, поэтому «сохрани картинку» = долгий тап/ПКМ по `<img>` или `shareContent`.
- Хэш-роутинг, не history API.
- SDK грузи со `huevo.su`, а не копией у себя.

## Cloudflare / окружение

- R2 требует включения в панели и карты (`code 10042`). Малые картинки можно хранить в D1 BLOB.
- `wrangler d1 migrations apply --remote` иногда падает с `fetch failed` по сети: повтори.
- `wrangler dev` держит порт: перед повторным запуском убей процесс (`taskkill //F //PID …` в Git Bash).
- `wrangler secret put` из пайпа не пишет секрет в историю; не печатай секреты в выводе.
- Статика с SPA-фолбэком перехватывает всё, кроме `run_worker_first`: добавляй туда `/api/*` и `/img/*`.
- На прод-базе стартовые данные (seed) вставляются при первом запросе, если таблица пуста. Для больших seed лучше миграция.
- Windows + Git Bash: многострочные heredoc с кавычками/обратными кавычками ломаются. Пиши файлы через инструмент записи. Python для правок запускай с `-I` и `-X utf8` (кириллица в консоли).
- Chrome headless для скриншотов: `chrome.exe --headless=new --window-size=W,H --virtual-time-budget=6000 --screenshot=out.png URL` (редактор и страницы с запросами нужно дать время).

## Данные и безопасность

- `hu_start` может прислать любой автор ссылки: ищи по коду в БД, не доверяй как команде.
- Не доверяй `intent_id`, пришедшему от клиента, без проверки, что платёж принадлежит игроку из сессии и приложению.
- `user_id` платежа берётся из сессии, а не из тела запроса.
- Сервер принимает загрузки только JPEG с проверкой сигнатуры и лимитом размера.
- Комментарии, названия, имена: фильтр ссылок, лимит длины, рендер только текстом.
- Разделяй «скрыть» (обратимо) и «удалить» (навсегда) в админке, спрашивай подтверждение при удалении.
- Сид-тесты и изображения с авторскими правами (персонажи, фото артистов) не клади в репозиторий. Фото от владельца/пользователя загружаются им самим.
